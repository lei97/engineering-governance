## 两轮实验能解释到哪里

| 对照 | 实际观察 | 结论边界 |
| --- | --- | --- |
| E001 · Markdown 与当前 YAML | 两组在六项可完整比较的判据上均无组内冲突。两份 YAML 答卷共同漏掉字段与字符上限的边界。 | 两组材料均未明示该边界，统一指令也未点名第六项。可以确认有共同遗漏，遗漏原因仍未确定。 |
| E002 · 当前 YAML 与显式时间语义 YAML | 两组各答对 28/28 项适用约束和 14/14 项轨迹汇总。依据齐全的轨迹分别为 14/14 和 12/14。 | 当前 YAML 在本案已达判定上限，正确率无法进一步提高。两份显式版答卷的 T2 结论正确，但没有说明完整记录如何排除取消自身的同值写入。 |
| 表达成本 | E001 正文从 197 增至 261 字符。E002 正文从 450 增至 880 字符，增加 430 字符（95.6%）。 | 两轮均缺少人类可读性、编写与实际作答用时的直接测量。字符数只反映篇幅。 |

每轮只覆盖一个案例和一个模型配置，每组两份独立答卷。E002 的轨迹与单项判定是答卷内重复观察。现有表达在本案已让读者完成判定。等义内容和共用证据规则也可能降低了两种格式的区分度。两种解释可以同时成立，现有实验无法判定各自的影响。后续分别评阅读者间一致性、与作者意图的一致性，以及结论和依据的覆盖程度。 [E001 材料复核](../experiments/E001/cases/REQ-100/run-01/README.md#分发材料复核) · [E002 T2 原句](../experiments/E002/run-01/review.md#解释充分性)

## 最小充分表达是待检验的方向

先在 `statement` 和 `acceptance` 写清会改变允许行为或验收的语义。以 E002 为例，相关信息包括同一操作的起止事件、比较的对象和属性、并发权限、直接写入与因果归属。证据另须说明观测的区间、路径覆盖、完整性与归属。结论、理由和证据可逐项对应。规则空白保留为未规定，已适用规则缺少证据时保留为证据不足。 [E002 业务与证据契约](../experiments/E002/README.md)

同一业务事实可维护在一处，并在需要时引用。重复抄写会拉长文本，修改时也需要同步多处。E002 把同一组事实重新组织为显式键、事件标识及对应引用。整组对照无法判断哪些单个构件有独立价值。若真实误读或验收困难能定位到具体语义边界，再比较短的受控表达与候选结构能否改善判断，并计入共享定义和维护成本。

## 下一次选题的门槛

优先选一条已有授权来源的真实需求。保留现有表述和可回溯的评审分歧、互相冲突的验收用例或交付返工，指出哪项判断会改变工程结果。由作者确认意图及未规定事项，配上可复查的运行证据和它的覆盖范围。比较不同表达时保持业务事实、证据和任务等义，并单独记录人的阅读、编写和修订成本。

异步设备任务是一条候选线索。如果接纳、执行完成或资源释放的不同解释会改变设备何时可接受下一任务，可以用原始需求、评审分歧和对应的事件轨迹定位失效边界。目前仓库中的取消探索样例缺少原始授权材料，E002 使用的是合成案例。设备任务仍需收集能支持上述判断的真实材料。 [原包样例证据边界](v0.1-review.md#原包样例暴露的一个分歧)
