# E001 首轮实验 · 同一需求的解释对照

给定同一条经作者确认的需求，普通自然语言与受约束的 YAML 会让读者对哪些行为作出不同判断？首轮选标准模式，比较解释分歧、遗漏、额外假设和表达成本。[首个案例](cases/REQ-100/record.md)已采集四份独立答卷，并完成基于作者判据的匿名 Agent 评阅。[分组汇总](cases/REQ-100/run-01/README.md#匿名评阅后的分组汇总)

## 准备两份等义材料

1. 需求作者选一条真实需求，记录授权来源及版本。先写下能决定验收的判定点、预期答案及仍未规定的边界。判据单独保存，评阅时使用。
2. 用普通自然语言把需求写成一份 Markdown，记为 A。将相同事实用当前 Schema 写成 YAML，记为 B。两份材料提供相同的术语定义、来源信息和边界条件。若整理 B 时发现漏掉了一个事实，请作者裁定后同步到 A，再冻结两版。
3. 作者对照判据核对两份材料。B 通过仓库校验器后，记录两版的文件版本、正文与所需定义的字符数、编写和修订时间。校验在分发前完成。[记录 Schema](../../schemas/knowledge.schema.json) · [校验器](../../scripts/validate_truth.py)

## 独立作答

每位读者只看一种表述和下列同一条指令。对每个参测模型，两组使用相同版本、设置和可用材料范围，分别开独立的新会话，随机安排作答次序。计算组内分歧至少需要两份可比较的独立答卷。要衡量人的可读性，可另请未参与编写的人直接盲读并作答。作者判据和其他答卷在作答结束后才用于评阅。

> 请仅依据所给材料，复述这项需求的前提、允许行为、禁止行为和完成条件。说明失败时能确定什么，并为每项判断指出依据。遇到影响验收而材料未规定的事项，写“未规定”，并写出需要作者裁定的问题。

## 评阅与结论

作者按冻结的判据逐项评阅匿名答卷，先记判定和依据，再汇总 A、B。意思相同的复述记作一致。作者判据中明确列为“未规定”的问题，答“未规定”是正确识别边界。

| 观察项 | 记录方法 |
| --- | --- |
| 解释分歧 | 同一判定点上，组内读者得出不同验收结论则记 1 项。列出有分歧的判定点数与总数。 |
| 遗漏、额外假设、误读 | 每份答卷分别列出漏掉的必要条件、无依据新增的规则，以及与作者判据冲突的解释。保存原句和所属判定点，即使全组答案一致也核对原意。 |
| 表达与阅读成本 | 并列记录两版字符数、作者编写及修订用时、读者作答用时。能取得 token 数时注明所用模型。 |

按读者类型和模型版本报告原始计数、分母及具体例子。若 B 减少了分歧和无依据的断言，还要查看遗漏、误读和编写成本是否增加。成本取舍由作者结合该案例判断。若读者暴露出判据本身有歧义，保留本轮记录，新一轮再修订材料。单个案例只形成该案例的结论。[实验记录模板](record-template.md)
