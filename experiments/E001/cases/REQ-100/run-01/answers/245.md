**前提**

- REQ-100 适用于已确认的需求。REQ-100 本身的状态为 `accepted`。依据是正文的 `status` 和“对已确认的需求”，以及 SRC-100 的“在确定的需求下”。
- 同一份 YAML 需求描述是真源，也是作者和 Agent 核对理解的共同依据。依据是正文“以 YAML 管理真源”和第一条验收条件。

**允许行为**

- 用简洁的表述写明会影响行为的必要前提。依据是正文 `statement`，以及 SRC-100 提出的减少隐含假设、保持描述简洁的目的。
- 作者和 Agent 可以各自复述需求。作者可以直接阅读同一份需求描述，核对 Agent 复述的行为是否符合其意图。依据是两条验收条件。

**禁止行为**

- 以其他描述取代 YAML 作为已确认需求的真源。依据是正文“以 YAML 管理真源”。
- 省略会影响行为的必要前提，或在核对时把额外假设当成已经确认的前提。依据是正文要求写明必要前提，第二条验收条件要求能定位额外假设。

**完成条件**

1. 作者能直接阅读同一份需求描述，并据此核对 Agent 复述的行为是否符合其意图。依据是第一条验收条件。
2. 对照作者和 Agent 的复述时，能定位出现的前提遗漏、额外假设或相互冲突的解释。依据是第二条验收条件。

**失败时能确定什么**

- 如果作者无法依据同一份描述核对 Agent 的复述，可以确定第一条验收条件未满足。如果对照两份复述后，已观察到的差异仍无法定位，可以确定第二条验收条件未满足。依据分别是两条验收条件。
- 如果差异已经定位，可以确定分歧涉及哪项前提、假设或解释。单凭分歧无法确定应采用哪种解释，或问题出在 YAML 描述还是某一方的复述。依据是第二条要求定位差异，第一条把是否符合意图交由作者核对。

**影响验收的未决事项**

| 未决事项 | 需要作者裁定的问题 | 依据 |
| --- | --- | --- |
| 必要前提的判定标准未规定 | 哪些会改变行为的情形必须写入 YAML？有争议的前提如何认定？ | 正文要求写明必要前提，未给出判定标准。 |
| 发现分歧后的通过标准未规定 | 能定位分歧是否足以通过验收，还是须由作者裁定、更新 YAML，并重新核对到双方理解一致？ | 两条验收条件要求能核对、能定位。SRC-100 提出一致性的目标，未规定分歧解决后的验收步骤。 |
| 验收证据未规定 | 应以什么材料证明作者已完成核对，以及对照时能够定位差异？ | 两条验收条件描述了应具备的能力，未规定证据形式。 |
