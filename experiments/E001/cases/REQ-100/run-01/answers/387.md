### 前提

- REQ-100 适用于已确认的需求。REQ-100 的状态是 `accepted`，其来源 SRC-100 也已确认。依据为 REQ-100 的 `status`、`origin`、`statement` 及 SRC-100 的来源说明。
- 以 YAML 管理需求真源，在同一份需求描述中简洁写明会影响行为的必要前提，供作者和 Agent 核对理解。依据为 REQ-100 的 `statement`。SRC-100 说明了目的，即尽量减少隐含假设，让双方的描述简洁、无歧义，并保障一致性。

### 允许行为

- 作者可以直接阅读同一份需求描述，用自己的意图核对 Agent 复述的行为。依据为 REQ-100 的第一条 `acceptance`。
- 作者和 Agent 可以对照各自的复述，指出遗漏的前提、额外假设或相互冲突的解释。依据为 REQ-100 的第二条 `acceptance`。

### 禁止行为

- 以其他载体取代 YAML 的真源地位，或省略影响行为的必要前提，均不符合 REQ-100 的 `statement`。
- 对复述的措辞、辅助材料和核对工具，材料未规定独立禁令。REQ-100 的 `acceptance` 关注作者能否核对行为，以及双方能否定位理解差异。

### 完成条件与失败判断

- 作者能直接阅读同一份描述，并据此核对 Agent 所述行为是否符合其意图。若作者无法完成这个核对，可以确定第一条 `acceptance` 未满足。若作者能够核对并发现行为偏离其意图，可以确定双方对该行为存在理解差异。
- 对照双方复述时，能够定位出现的遗漏前提、额外假设或冲突解释。若已发现差异却无法定位，可以确定第二条 `acceptance` 未满足。能定位差异本身符合该条要求。依据为 REQ-100 的第二条 `acceptance`。
- 若发现差异，材料只支持报告能从复述中定位的内容。差异源于需求表述还是复述过程、应采用哪一方的解释、是否需要修改需求，均需进一步证据或作者裁定。REQ-100 的两条 `acceptance` 只规定了核对和定位。

### 需要作者裁定

- **未规定**哪些边界情形属于必须写明的行为前提。哪些输入、状态或例外会改变预期行为，必须在 YAML 中写明？
- **未规定**复述的载体、验收记录或确认方式。什么证据足以表明作者已能直接核对，以及双方已能定位差异？
- **未规定**找到差异后是否必须修订、消除分歧并重新核对才算验收完成。验收以能够定位差异为止，还是还需要作者确认采纳的解释并复核？
