- REQ-100 已确认，来源 SRC-100 也已确认。其适用对象是已确认的需求。〔依据：需求正文第 1、3 段，SRC-100 的来源状态〕
- 已确认的需求以 YAML 为真源。需求描述应简洁，并明示影响行为的必要前提，供作者和 Agent 核对理解。〔依据：需求正文第 1 段，SRC-100 关于减少隐含假设、使描述简洁并避免歧义的说明〕

## 允许行为

- Agent 可以依据这份需求描述复述行为。作者可以直接阅读同一份描述，核对 Agent 的复述是否符合自己的意图。〔依据：需求正文第 1、2 段〕
- 可以对照作者和 Agent 的复述，指出具体遗漏了哪个前提、增加了哪个假设，或哪两种解释相互冲突。〔依据：需求正文第 2 段〕

## 禁止行为

- 省略会影响行为的必要前提，或把额外假设当作已确认的条件。额外假设可以作为差异指出。〔依据：需求正文第 1 段要求明示必要前提，第 2 段要求能定位额外假设〕
- 以各自的描述取代双方共同核对的 YAML 真源。〔依据：需求正文第 1 段的真源要求和第 2 段的同一份描述要求〕

## 完成条件和失败判定

- 已确认的需求以 YAML 记录，表述简洁，影响行为的必要前提已写明。作者能直接用同一份描述判断 Agent 的行为复述是否符合自己的意图。出现遗漏、额外假设或解释冲突时，对照两份复述能定位到具体差异。〔依据：需求正文第 1、2 段〕
- 已定位差异时，可以确定具体分歧。发现两份复述有差异却无法定位时，可以确定定位要求未满足。作者无法用同一份描述判断复述是否符合其意图时，可以确定核对要求未满足。材料未指定冲突解释的裁定规则。〔依据：需求正文第 2 段只规定核对和定位应当可行〕
