# E002 实验 · 取消探索的时间语义

**H2** 在业务事实相同的条件下，检验显式表达事件边界、状态参照和行为归属能否减少 Agent 的符合性误判，同时保留人类可读性和较低的表达成本。 [E001 首轮结论](../E001/cases/REQ-100/run-01/README.md#阶段性结论)

本实验从 [取消探索样例](../../docs/v0.1-review.md#原包样例暴露的一个分歧) 提取问题。2026-11-22，作者在本次对话回复“确认四项，开始准备并采集”，确认以下业务口径用于本实验的合成案例。

## 业务契约 · 四项作者裁定

| 确认事项 | E002 实验口径 |
| --- | --- |
| 事件边界 | 以同一取消请求为单位，从系统开始处理起，到该请求报告成功前为写入约束的区间。比较时分别取探索开始前、取消处理开始前及报告成功后的状态。 |
| 并发规则 | 探索与取消期间均允许独立且合法的其他编辑修改同一正式作品。 |
| 行为归属 | 直接写入归属于实际执行写入的操作。由取消触发的下游正文变化计入因果影响。成功取消期间禁止其自身直接写入（含同值写入），也禁止它直接或间接造成正文变化（含随后恢复）。 |
| 状态范围 | 比较同一正式作品的正文值。版本号和时间戳等属性留在比较范围之外。两种端点比较单独记录为观察。 |

超时后的回滚、重试，以及报告成功后的延迟写入均保持未规定。四项裁定只用于本实验案例。

## 逐项判定口径

先确定需求是否对本题行为给出适用约束，再用轨迹判断该约束是否满足。没有适用约束时即可记录未规定。有适用约束时，再判断证据是否充分。

| 结果 | 判定依据 |
| --- | --- |
| 满足 | 适用约束明确，证据足以证明本次行为符合该约束。 |
| 违反 | 适用约束明确，证据足以证明本次行为违反该约束。 |
| 未规定 | 需求对题目所问的行为没有给出适用约束。 |
| 证据不足 | 已有适用约束，但给出的轨迹无法确定本次行为是否符合。 |

例如，已明确禁止取消写入时，端点正文相同仅足以判断端点相等，写入约束仍为证据不足。并发写入权限若未在材料中声明，则这一权限问题为未规定。轨迹中一次并发写入的存在本身无法证明其获准或被禁止。

## 证据契约 · 判定所需的观察

| 判断 | 足以支持的证据 |
| --- | --- |
| 两个参照点的正文相等或不同 | 两个参照都能定位到同一正式作品、各自的边界事件及对应的正文值。 |
| 直接禁写约束满足 | 轨迹明确覆盖目标正文在区间内的全部直接写入路径，包含同值写入和随后恢复的写入。记录完整，写入的操作归属与先后可核对，且未发现归属本次取消的直接写入。 |
| 直接禁写约束违反 | 至少有一条发生在区间内、归属本次取消且写入目标正文的直接写入证据。该次证据可复核即可确认违反。 |
| 因果约束满足 | 轨迹完整覆盖区间内所有正文变化，含下游路径和后来恢复的变化，并能排除其中任何变化由本次取消引起。 |
| 因果约束违反 | 至少有一次发生在区间内的正文变化，有直接写入证据或可复核的触发链将变化归因于本次取消。共享标识和相邻时间可用于查找关联事件，归因还需要触发与结果对应的证据。 |

用缺少某类事件来支持“满足”时，先核对记录的覆盖范围、采集完整性与操作归属。若边界事件与写入的先后、路径覆盖或归属缺失，且没有足以判定违反的证据，该项记为证据不足。完整记录只支持对所声明的作品属性、时间区间和写入路径作缺失判断。范围以外的副作用仍需相应证据。两组收到相同的覆盖声明和轨迹。

## 两种 YAML 表达

- A 使用当前 v0.1 的 `statement` 和 `acceptance`，在字段中明确表达事件、边界、参照对象、并发规则和行为约束。
- B 在实验材料中分别标识 Event、Temporal Scope、State Reference 和 Constraint，以显式引用连接事件、状态及相关操作。

两组材料以作者裁定和证据契约为依据。两组使用相同的轨迹、证据覆盖声明、题目和术语定义。若整理 B 时发现缺少前提，先由作者裁定，再同步到 A。A 在分发前用当前 Schema 校验。B 的新增表达仅用于实验材料。 [A 当前 YAML](materials/current/REQ-201.yaml) · [B 显式表达 YAML](materials/explicit/REQ-201.yaml) · [实验来源](materials/current/SRC-201.yaml)

## 共同判定题

对 T1 至 T6，先判断成功完成时的正文是否分别与探索开始前、取消开始前相同，再分别判定直接写入约束与因果约束。T7 判定超时后的回滚和重试要求。每个判定需指出适用规则和轨迹证据，再汇总本题结果。

任一已明确的适用约束违反，汇总记为违反。其余情况下，只要有适用约束证据不足，汇总记为证据不足。已有明确约束且全部满足时记为满足。题目所问行为没有适用约束时记为未规定。汇总时保留各列判断及其理由。

甲、乙表示两个不同的正文值。T1 至 T5 明确提供完整区间记录，覆盖目标正文的全部直接和下游写入路径，包括同值写入及最后被恢复的变化。操作归属、因果链、正文取样及事件先后皆可核对。T6 仅有正文取样值，缺少上述区间证据。T7 单独询问超时规则。

| 轨迹 | 探索开始前 → 取消开始前 → 成功完成后 | 已知行为或证据 |
| --- | --- | --- |
| T1 · 取消前合法编辑 | 甲 → 乙 → 乙 | 另一操作在取消开始前写入乙。完整的取消区间记录中无正文写入条目。 |
| T2 · 取消中合法编辑 | 甲 → 甲 → 乙 | 取消期间，独立且合法的另一操作把正文改为乙。可确认该编辑与取消无因果关系。 |
| T3 · 取消写入后恢复 | 甲 → 甲 → 甲 | 取消直接写入乙，随后再写回甲。 |
| T4 · 取消写入同值 | 甲 → 甲 → 甲 | 记录证实取消完成了一次写入，正文仍为甲，期间也无其他正文变化。 |
| T5 · 取消触发间接变化 | 甲 → 甲 → 乙 | 取消发送更新请求。同一请求的关联记录表明，下游操作响应请求并在取消期间写入乙。取消自身没有直接写入。 |
| T6 · 同值但缺少归属 | 甲 → 甲 → 甲 | 只保存三个取样点。区间事件记录和写入归属缺失。 |
| T7 · 超时 | 甲 → 甲 → 无成功完成事件 | 取消开始后发生超时。判断材料是否规定此时必须回滚或重试。 |

## 分发、记录与判定

以干净工作树中的固定 Git 提交锁定需求、定义、材料和判据版本。保存无法从该提交恢复的外部输入。另记录每次实际交付的材料、顺序、提示及模型版本和设置。两组按模型匹配设置和有效答卷数，各至少两份独立答卷。随机安排作答次序，每次只读一份 YAML，作者评阅时隐藏组别。

逐题记录误判、遗漏、额外假设，并区分把“未规定”自行补成规则、把“证据不足”判为通过或不通过。报告各组分母和原句，另记正文及所需定义的字符数、编写和修订用时、作答用时。人类可读性单独记录实际读者的反馈和依据，缺项标为未测。若 B 在等义条件下减少误判，并且作者认为成本可接受，本案例支持继续试验。结果只适用于本案例，可用于比较受控表达约定与候选字段的取舍。
