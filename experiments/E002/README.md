# E002 实验草案 · 取消探索的时间语义

**H2** 检验将事件、时间范围和状态参照写成可引用的结构，能否减少对同一条需求的验收误判。H1 的等义阅读对照沿用 [E001](../E001/README.md)。H3 关注编写者能否借助模板发现未声明的前提，需另行对照独立编写过程。

本草案从 [取消探索样例](../../docs/v0.1-review.md#原包样例暴露的一个分歧) 提取问题。下列行为假设和轨迹用于演练，待作者确认后才可作为正式实验材料。

## 待作者确认的范围

| 表达要素 | 实验候选口径，待作者确认 |
| --- | --- |
| Event · 事件 | 按取消请求的身份关联开始和完成事件。开始指系统着手处理该请求，成功完成指系统完成处理并报告成功。另保留同一作品的探索开始事件供比较。 |
| Temporal Scope · 时间范围 | 比较处理开始前与报告成功后的正文。写入约束覆盖从开始处理起到报告成功前的区间。边界写入缺少可靠顺序时，区间判定记为证据不足。超时回滚、重试及成功完成后的延迟写入另列为未规定。 |
| State Reference · 状态参照 | 只比较同一正式作品的正文值。快照记录指定事件上的正文值。版本号和时间戳在本实验的比较范围之外。 |
| Constraint · 约束 | 探索与取消期间均允许独立且合法的其他编辑。成功取消的验收检查直接写入和因果影响，同值写入也属于写入。通过关联事件证明因果归属，包括被取消操作触发的下游写入。端点正文相等单独记录为观察。 |

演练对成功取消分别检查直接写入和因果影响。取消自身不得直接写入正式正文，也不得直接或间接造成区间内的正文变化。即使随后恢复，区间内确实发生过的变化仍计入。“取消前后正文相等”单独记录为状态判断。超时后的要求暂记为“未规定”。这些是拟议的实验判据，作者可调整后重新核对轨迹。

## 逐项判定口径

| 结果 | 判定依据 |
| --- | --- |
| 满足 | 适用约束明确，证据足以证明本次行为符合该约束。 |
| 违反 | 适用约束明确，证据足以证明本次行为违反该约束。 |
| 未规定 | 需求对题目所问的行为没有给出适用约束。 |
| 证据不足 | 已有适用约束，但给出的轨迹无法确定本次行为是否符合。 |

例如，已明确禁止取消写入时，端点正文相同仅足以判断端点相等，写入约束仍为证据不足。并发写入权限若未在材料中声明，则这一权限问题为未规定。轨迹中一次并发写入的存在本身无法证明其获准或被禁止。

## 两种 YAML 表达

- A 使用当前 v0.1 的 `statement` 和 `acceptance`，在字段中明确表达事件、边界、参照对象、并发规则和行为约束。
- B 在实验材料中分别标识 Event、Temporal Scope、State Reference 和 Constraint，以显式引用连接事件、状态及相关操作。

作者先冻结判据，再核对两份材料的事实、约束、术语、来源和未规定事项等义。两组使用完全相同的轨迹、题目和术语定义。若整理 B 时发现缺少前提，先由作者裁定，再同步到 A。A 在分发前用当前 Schema 校验；B 的新增表达仅用于实验材料。

## 共同判定题

对 T1 至 T6，先判断成功完成时的正文是否分别与探索开始前、取消开始前相同，再分别判定直接写入约束与因果约束。T7 判定超时后的回滚和重试要求。每个判定需指出适用规则和轨迹证据，再汇总本题结果。

甲、乙表示两个不同的正文值。除注明缺失的轨迹外，给出的区间记录完整，正文取样与事件的先后已确定。

| 轨迹 | 探索开始前 → 取消开始前 → 成功完成后 | 已知行为或证据 |
| --- | --- | --- |
| T1 · 取消前合法编辑 | 甲 → 乙 → 乙 | 另一操作在取消开始前写入乙。取消期间没有写入。 |
| T2 · 取消中合法编辑 | 甲 → 甲 → 乙 | 取消期间，独立且合法的另一操作把正文改为乙。可确认该编辑与取消无因果关系。 |
| T3 · 取消写入后恢复 | 甲 → 甲 → 甲 | 取消直接写入乙，随后再写回甲。 |
| T4 · 取消写入同值 | 甲 → 甲 → 甲 | 记录证实取消完成了一次写入，正文仍为甲，期间也无其他正文变化。 |
| T5 · 取消触发间接变化 | 甲 → 甲 → 乙 | 取消发送更新请求。同一请求的关联记录表明，下游操作响应请求并在取消期间写入乙。取消自身没有直接写入。 |
| T6 · 同值但缺少归属 | 甲 → 甲 → 甲 | 只保存三个取样点。区间事件记录和写入归属缺失。 |
| T7 · 超时 | 甲 → 甲 → 无成功完成事件 | 取消开始后发生超时。判断材料是否规定此时必须回滚或重试。 |

## 作者评阅底稿

## 分发、记录与判定

以干净工作树中的固定 Git 提交锁定需求、定义、材料和判据版本。保存无法从该提交恢复的外部输入。另记录每次实际交付的材料、顺序、提示及模型版本和设置。两组按模型匹配设置和有效答卷数，各至少两份独立答卷。随机安排作答次序，每次只读一份 YAML，作者评阅时隐藏组别。

逐题记录误判、遗漏、额外假设，并区分把“未规定”自行补成规则、把“证据不足”判为通过或不通过。报告各组分母和原句，另记正文及所需定义的字符数、编写和修订用时、作答用时。若 B 在等义条件下减少误判，并且作者认为成本可接受，本案例支持继续试验。结果只适用于本案例，重复案例可为结构是否值得固化提供证据。
