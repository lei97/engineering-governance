## P2 · 首例证据复核

提取会话生成 10 个实体、10 条主张和 12 条有向关系。它把评审报告的运行结果与从代码推导的误命中机制分别建模。程序核对了关系端点和全部证据行号。另一独立 Agent 按原始片段复核内容支持、状态、谓词和方向。 [候选工程知识图](case-001/extraction.json) · [逐条评阅](case-001/evaluation.json)

| 核对项 | 首例结果 |
| --- | --- |
| 主张与状态 | 10/10 条获证据支持，报告、观察、推断和规则的归类与材料一致。 |
| 有向关系 | 11 条获支持，1 条部分获支持。`can_satisfy` 的源是诊断类别，证据实际支持的是带特定文件路径的诊断实例。目标是描述断言的主张，关系真正指向的是其中的子串检查条件。 |
| 候选参考覆盖 | 六项参考主张的信息均可定位。其中两项需要组合多条主张，补齐验收项后的误通过机制没有单条完整的条件推断。两条候选参考关系中，一条由拆开的两条边表达，另一条缺少同方向的显式边。 |

引用可解析只说明原文能找到。证据支持、关系方向及语义仍需逐项复核。本轮是单个已修复缺陷上的 Agent 初评，候选判据待人工确认，尚无复用收益或审阅工时数据。

### 独立参考与错误关系检测

第二份候选判据由只见 D1–D6 的独立会话编写。10 条参考主张中，原图明确覆盖 8 条、部分覆盖 1 条、遗漏 1 条。人工底稿列出了 10 条原主张、12 条原关系、独立参考的对应情况及拟供复用的子集。 [人工复核底稿](case-001/human-review.md) · [独立参考](case-001/independent-reference.json)

用四条受证据支持的参考边，各构造一个错误谓词、反向、过期修订或无依据的充分因果。将四条错误边与原参考集合比较，有向端点 F1 为 `0.75`，字面 Triple F1 为 `0.25`，再纳入修订与适用条件后为 `0.00`。四条正确边在三种口径下均为 `1.00`。两套边由构造得出，用于定位指标盲区。 [固定对照及答案](case-001/controls.json)

独立评阅会话只见混排候选和原文，接受四条有支持的关系，拒绝并正确归类四条错误关系。一个相同三元组因为沿用错误修订仍会命中字面评分。`guarantees` 控制项也表明，需要单独核对缺失来源诊断、文件名和断言条件，避免把因果贡献升级成单独充分的原因。 [盲评与计分](case-001/controls-result.json)

后续把五项分别记录。Triple F1 依已确认的实体、谓词和有向边统计。Evidence Support 逐条核对原始证据。Claim Recall 以人工确认的独立清单为分母。Scope Correctness 单列适用版本与前提。Unsupported Inference 记录无支持推断及未经支持升级为确定结论的实例。控制实验覆盖了匹配口径和错误识别，工程案例的人工判据仍待完成。
