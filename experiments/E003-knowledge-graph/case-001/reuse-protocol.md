## 条件与任务

每位 Agent 在单独的临时目录使用 `83a2120` 导出的代码快照。两组各开两个独立会话，随机分配，并使用同一模型版本、依赖、工具权限和作答预算。两组都收到同一份修复任务、同一份 D1 问题与复现记录，并可读取对应的原始代码与样例。B 组还收到经作者确认的图谱摘录，摘录中的事实和证据均来自两组共有材料。将作答环境的文件访问范围限定在分配的输入和修复前快照，评阅方单独保管修复提交 `093f88d`、修复后测试和留出结果。

统一任务为「修复 #13，使反例测试能可靠发现目标诊断未出现的情况，同时保留现有校验行为。交付可应用的补丁，说明判断依据及实际运行的验证。」参与者材料只包含本段任务和所属条件的输入。执行时记录分发版本，并将各会话的补丁与运行日志分别保存。

## 留出验收

在另一份干净的 `83a2120` 快照应用每个补丁，用同一套留出检查运行。以固定修复的行为校准检查，按结果验收不同实现。两端已校准未变异反例、补齐验收项、同文件错误诊断和五项 #16 回归。 [固定修复前后复跑记录](holdout.json) · [留出验收校准](reuse-calibration.json)

| 检查 | 预期行为 |
| --- | --- |
| 补丁与正常基线 | 补丁可应用，既有正例校验通过，未变异的反例批次按预期拒绝，完整单测及 #16 批量诊断回归通过。 |
| 补齐目标验收项 | 在临时副本给目标反例补齐合法 `acceptance`，验证原反例断言因目标诊断消失而失败。 |
| 错误诊断 | 补齐验收项后仅让同一文件出现另一项真实诊断，验证它无法代替预期诊断使反例断言通过。 |
| 其他诊断 | 独立文件的既有诊断仍可检出，仍能归到正确文件。另核对校验规则与 #16 的既有行为。 |

## 记录与边界

先隐藏组别逐份评阅补丁、四项验收、失败诊断和是否有无依据假设，再汇总每组两份独立结果。记录输入量、可见工具调用和墙钟用时。B 组可报告采用或弃用的主张 ID 和据此发生的动作。评阅用会话中的引用、补丁位置和验证日志核对这些动作。A 组用原始文件与证据定位做同样的记录。自报帮助另记，单凭引用无法判定某条知识造成了结果差异。

图谱整理、人工审阅和修订的实测工时单列。缺少记录时保留为未测。首轮衡量同一历史缺陷上的复用效果，原始评审已解释缺陷成因，正确率可能接近上限。结果仅适用于本次重放，跨案例迁移仍需新任务验证。
