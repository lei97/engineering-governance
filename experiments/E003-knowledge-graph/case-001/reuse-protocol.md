# E003 · case-001 P3-A 同案知识辅助协议

P3-A 以 #13 修复前的代码做同案历史重放，比较经过整理的工程知识能否帮助 Agent 交付正确修复。2026-11-23，作者确认六条主张、两条关系及其适用条件用于本轮。任务、实际分发版本、随机分配及留出验证在派发前固定。 [人工裁定底稿](human-review.md) · [统一任务](reuse-task.md) · [B 组知识摘录](reuse-knowledge.md) · [冻结与校验记录](reuse-readiness.json)

## 条件与任务

两组各开两个独立会话，随机分配，匹配模型版本、依赖、工具权限和作答预算。每位 Agent 在单独的临时目录使用 `83a2120` 导出的无 Git 历史快照。两组都收到同一份任务和同一份 D1–D6。B 组增加经作者确认的知识摘录，事实和证据均取自共有材料。 [共有来源](sources.json)

评阅方单独保管修复提交 `093f88d`、修复后测试、留出结果和含修复源码的错误关系对照。作答包只包含分配的材料和修复前快照。若执行环境仍能读取作答包以外的文件或访问网络，记录实际访问边界及可核对的访问日志。访问了留出材料的答卷单列为污染样本。访问无法审计时，把该限制作复盘记录。执行时按各会话保存分发摘要、补丁和运行日志。

## 留出验收

在另一份干净的 `83a2120` 快照应用每个补丁，用同一套留出检查运行。以固定修复的行为校准检查，按结果验收不同实现。两端已校准未变异反例、补齐验收项、同文件错误诊断和五项 #16 回归。 [固定修复前后复跑记录](holdout.json) · [留出验收校准](reuse-calibration.json)

| 检查 | 预期行为 |
| --- | --- |
| 补丁与正常基线 | 补丁可应用，既有正例校验通过，未变异的反例批次按预期拒绝，完整单测及 #16 批量诊断回归通过。 |
| 补齐目标验收项 | 在临时副本给目标反例补齐合法 `acceptance`，验证原反例断言因目标诊断消失而失败。 |
| 错误诊断 | 补齐验收项后仅让同一文件出现另一项真实诊断，验证它无法代替预期诊断使反例断言通过。 |
| 其他诊断 | 独立文件的既有诊断仍可检出，仍能归到正确文件。另核对校验规则与 #16 的既有行为。 |

逐项记录实际运行到的测试及失败原因。变异测试需命中目标诊断断言。其他诊断按共同的既有文件和报错内容核对，历史修复新增样例的诊断数只用于校准记录。

## 记录与边界

先隐藏组别逐份评阅补丁、四项验收、失败诊断和是否有无依据假设，再汇总每组两份独立结果。记录输入量、可见工具调用和墙钟用时。B 组可报告采用或弃用的主张 ID 和据此发生的动作。评阅用会话中的引用、补丁位置和验证日志核对这些动作。A 组用原始文件与证据定位做同样的记录。自报帮助另记，单凭引用无法判定某条知识造成了结果差异。

图谱整理、人工审阅和修订的实测工时单列，缺少记录时标为未测。每组两个独立结果只作描述性比较。原始评审已解释缺陷成因，正确率可能接近上限。B 组同时得到关系结构、提前整理的结论和人工筛选，这些因素的贡献当前设计无法分开。差异归属于本次知识辅助条件。

## P3-B · 跨任务知识复用

另选一个尚未解决且机制相关的工程任务。在新任务开始之前固定本轮产出的知识，原样供实验组使用。两组配对提供新任务与代码基线，记录适用条件冲突、实际使用的知识和验收结果。P3-B 单独归档，与 P3-A 的同案结果分别解释。新案例待选。
