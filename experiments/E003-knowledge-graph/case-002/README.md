留出验收在派发前校准。用多层目录和多个 `.yml` 检查逐文件报告，用仍含普通 `.yaml` 错误的混放批次检测是否过早返回，用改名后的来源检查索引边界。用合法批次与现有测试检查回归。以退出码、触发文件和目标诊断验收，允许无关诊断随合理输入变化。临时参考实现通过留出验收，原版以及漏报嵌套文件、提前返回、错误入索引、漏改名提示和误报目录的实现均未通过。 [留出验收](check.py) · [校准记录](calibration.json)

## 历史知识的适用性

四份报告均依据新基线审查 #13 的旧子串机制，定位本次漏报发生在文件发现。872 的原始报告核对了 `00-support/SRC-001.yaml` 和当前逐文件断言，并提议用同内容、不同后缀的样例验证文件发现。689 明确记录 `00-support/SRC-001.yaml` 和 `duplicate-id.yaml` 均声明 `SRC-001`，并记录了逐步改名的验证。872 的原始报告没有记载第二份声明或这次改名实验。补采的 770 验证了单一 `SRC-999` 来源改名后进入索引，605 用缺失的 `SRC-998` 重放旧子串的适用条件。 [原始答卷](submissions.json) · [独立证据审阅](review.md#原始报告证据审阅)

实验组织者用两份归档补丁分别重放了同一个三步验证。补齐 `acceptance` 后，改名零份或一份来源均未产生该需求的缺来源诊断。两份都改为 `.yml` 时，两份补丁都报告 `missing origin SRC-001`，其文件名可使人工重放的旧 `acceptance` 子串条件命中。复跑没有产生当前逐文件断言要求的精确缺字段诊断。这一结果表明，判断来源仍能否解析需要核对本次索引中是否还保留该 ID。C08 的历史结论保留原条件。由报告记录和补丁复跑均无法将这一行为归因于 B 组获得的摘录。 [三步复跑结果](submissions.json)
