### 首批

#### G

- **任务符合性。** `G.patch` 第 29–45 行仅为现有递归 `.yaml` 扫描加入小写 `.yml` 文件诊断。诊断附路径并提示 `use .yaml`。混合目录仍进入原有 `.yaml` 处理流程，`.yml` 从未进入该流程，因而不参与计数、解析或 ID 索引。只有 `.yml` 时返回逐文件错误和零记录。无匹配文件时保留原来的 `no .yaml files found`。命令仍沿用基线的错误行、汇总行和退出码。
- **范围。** 新增的拒绝条件是任务要求的小写 `.yml` 文件。`endswith` 和 `is_file` 分别约束大小写和实际文件，`.yml` 目录仍可作为扫描容器。后缀错误先于内容错误输出，输出格式保持原样。补丁未改动规范或 Schema，也未扩大文件后缀限制。
- **覆盖。** 第 62–118 行通过 CLI 检查纯 `.yaml` 通过、单个嵌套 `.yml` 失败、有效 `.yaml` 与同 ID `.yml` 混合时失败，以及多处 `.yml` 与无效 `.yaml` 混合时仍报告重复键、Schema 和 `origin` 错误。格式损坏的 `.yml` 只得到后缀诊断，名为 `archive.yml` 的目录本身没有诊断。第 1–24 行的正反样例内容相同并置于专用目录，原有正反样例集合及断言未改动。新增测试没有直接断言空目录诊断或 `relations` 引用，属于覆盖差异。
- **共享样例依赖。** 第 106–117 行复制共享的 `missing-acceptance.yaml` 和 `duplicate-key.yaml`。测试绑定前者缺 `acceptance` 且 `origin` 恰为 `SRC-001`，也绑定后者重复 `id`。在临时副本中，只把共享样例的 `origin` 改成 `SRC-777`，单独运行该后缀测试会因预期路径对应的来源 ID 不符而失败。给共享样例补上合法的 `acceptance` 后，错误数从预期的 5 降为 4。针对后缀行为的测试会随共享样例内容变动，属于维护成本。未发现当前快照上的实质性缺陷。

#### H

- **任务符合性。** `H.patch` 第 29–45 行将逐文件小写 `.yml` 诊断加入初始错误列表，同时保留 `.yaml` 候选列表。仅在两者均为空时沿用 `no .yaml files found`。其余情况进入原有 `.yaml` 处理和返回路径，`.yml` 不参与计数、解析或 ID 索引。诊断带路径和 `use .yaml` 提示，CLI 的错误行、汇总行和退出码沿用基线。
- **范围。** `endswith` 和 `is_file` 将拒绝范围限定为小写 `.yml` 文件。`.yml` 目录仍能纳入递归扫描。补丁未改动规范或 Schema，也未扩大文件后缀限制。第 56–84 行扩展共享负例清单校验以登记 `.yml`，同时继续按 `.yaml` 计算记录数。这改变了仓库测试所登记的样例集合。
- **覆盖。** 第 56–87 行将等内容的正反样例纳入共享验证。第 107–164 行检查混合有效记录、根目录和子目录的多个 `.yml`、被忽略内容的损坏 `.yml`、`.yml` 目录内的有效记录、仅嵌套 `.yml` 和空目录。混合错误测试检查重复键和 Schema 错误，并分别断言 `.yml` 的 ID 无法解析 `origin` 与 `derived_from`。纯 `.yaml` 通过在原有函数级测试中覆盖，共享正例数量断言由 5 更新为 6。
- **共享样例依赖。** 第 129–145 行读取共享的 `missing-acceptance.yaml`，主动设置 `origin` 和 `relations`，但依赖该样例仍缺 `acceptance`，也逐字节复制 `duplicate-key.yaml` 并断言重复 `id`。在临时副本中，将共享样例的 `origin` 改成 `SRC-777` 后，单独运行后缀测试仍通过。给该样例补上合法的 `acceptance` 后，错误数从预期的 5 降为 4，测试失败。接入共享清单还增加了对固定正例总数和负例登记的维护。未发现当前快照上的实质性缺陷。

#### 独立复验

在评阅目录内分别复制基线并使用 `git apply -` 应用补丁。使用已安装依赖和 Python 3.12 执行 `python -B -m unittest discover -s tests -q`，基线 8 项通过，G 与 H 各 12 项通过。独立 CLI 输入包含一个位于 `.yml` 子目录内的有效 `.yaml`、两个小写 `.yml`、一个大写 `.YML` 和一个 `.txt`。基线返回 0，汇总为 1 条记录和 0 个错误。G 与 H 均返回 1，汇总为 1 条记录和 2 个错误，恰好报告两个小写 `.yml` 文件。移除 `.yaml`、`.YML` 和 `.txt` 后，基线仅报告找不到 `.yaml`，两份补丁均返回 1、计数为 0，分别报告两个小写 `.yml` 的路径。

共享样例扰动只在补丁副本上运行对应的单项测试。结论限于给定快照、补丁及本机 Python 3.12 运行结果。临时副本已清理，输入材料保持原样。
