# YAML 记录校验：报告不受支持的文件后缀

现行 `specifications/yaml-profile.md` 要求记录文件以 `.yaml` 结尾。用户在校验目录混放有效 `.yaml` 和小写 `.yml` 时可以得到 PASS。在只有 `.yml` 的目录中，用户也无法从诊断定位被拒的文件。

请在分配的代码快照中修复此问题。扫描目录及子目录时，逐文件报告小写 `.yml` 的路径并提示改用 `.yaml`。一旦发现这类文件，命令应失败，且继续校验整批 `.yaml` 并报告其错误。`.yml` 不参与记录计数或 ID 索引。纯 `.yaml` 输入沿用既有行为。保留现行输出格式。大小写变体和其他扩展名超出此次范围。

交付可运行的改动和覆盖目标行为的正反样例与回归测试。报告你的定位依据、实际改动、验证命令与结果，以及你依据当前材料排除的解释和理由。如果本次证据支持补充、限定或修正以前的工程知识，指出旧结论的适用范围、新证据及建议；也可以说明为什么现有条目应保留。报告中分清实际操作和推断。

`prior-sources.json` 是两组共同可选的历史原始材料。可使用分配目录内提供的材料和已安装的 Python 依赖。将修改留在分配的 `repo/` 中，报告写入分配目录内的 `submission.md`。已有测试可以使用系统临时目录。请勿查看分配以外的项目、Git 历史、其他会话或网络，也勿修改输入材料。披露过程中实际使用的外部项目材料或工具限制。
