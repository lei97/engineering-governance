# E003 · P4 跨版本知识有效性草案

P3-A 和 P3-B 均未观察到验收通过率差异。P3-B 的 872 与 689 补丁在组织者复跑中表现一致，逐步改名的发现过程只记录在 689 的原始答卷。本轮评测判断及其证据，避免用最终代码行为推断会话做过的分析。 [P3-B 适用性复核](case-002/README.md#历史知识的适用性)

## 三组对照

所有会话收到同一份交接任务、原始历史资料和目标版本证据。证据可含代码、测试与实际运行记录。会话交付逐项判定、适用条件、证据定位和可选修订建议。

| 组别 | 材料 | 比较目标 |
| --- | --- | --- |
| A | 共同原始资料 | Agent 从原始材料恢复历史知识并核对当前状态的表现 |
| B | 共同资料，加线性经验摘要 | 相对于 A，预先整理历史知识的价值 |
| C | 共同资料，加显式关系图谱 | 相对于 B，相同知识采用关系结构的价值 |

从同一份历史主张清单生成 B、C 两组材料。每条保留主体、关系、客体、方向、肯定或否定、适用版本、条件、证据定位和主张状态。B 版用短句完整表达这些信息，C 版用显式边和限定条件表达。独立核对两版能恢复同一组主张与关系，记录遗漏、额外推断及跨条目限定差异，修正后再冻结。已确认的历史事实、当时的说法和推断须保留各自的证据状态。

附加材料只整理历史材料。目标版本证据、判定题与评分参考独立准备，B、C 附加材料中不包含针对题目的裁定或从新版本回填的结论。正式会话使用相同模型配置、任务顺序、工具权限和时间口径，均衡分配到三组并保留分配记录。可先评审一次原始资料组试答，检查题目是否仅凭表面线索就能命中。如果校准题趋于满分，保留这一结果，并用真实版本跨度或跨模块交接材料补充正式题目。

## 校准案例与候选判据

采用 Git 中 #16 的变更作为校准。旧版为 `9c38156fa8c277507ab30529af6d0480e8cbf833`，新版为 `83a21206ebf9e1addf6aa115a9f3c6427c2a40bf`。两版的 Schema 和规范内容相同，校验器对畸形字段和批次诊断的处理发生变化。这能用来区分规则、实现、运行观察与历史描述。

| 判定维度 | 候选问题 | 组织者参考依据 |
| --- | --- | --- |
| 仍适用 | 批次正常走完，已解析记录的字符串 `origin` 指向未注册 ID，旧缺来源判断能否复用？ | 两版的 `dangling-reference.yaml` 均输出 `missing origin SRC-999`。适用范围是本次索引和可执行到该检查的输入。 |
| 已过期 | 旧版 `relations: REQ-002` 导致批次中断，迁移后还应预测这个结果吗？ | 旧版触发 `AttributeError`，既无正常摘要也无逐条诊断。新版输出该字段的类型错误，同时报告独立记录的缺来源。 |
| 部分适用 | 来源的 `kind` 是列表时，能否沿用“来源存在且类型正确”的解释？ | 新版保留其字符串 ID，依赖它的记录无缺来源诊断。来源自身仍报告 `kind` 错误。删掉该来源后，同一依赖记录出现缺来源诊断。ID 可解析与来源类型合法须分别判断。 |
| 发现冲突 | 若把 #16 的历史描述解读为任意 `relations` 列表都会让旧版崩溃，如何处理同版本反例？ | 同一旧版上，空列表产生字段诊断并继续校验，非空列表触发 `AttributeError`。核查旧代码中 `or {}` 的分支，并限定历史描述的适用范围。 |
| 提出修订 | 历史实现里非字符串 ID 会使记录退出后续检查。目标版应如何更新这一条知识？ | 将 `id` 改为映射后，两版都报告 `[id]` 错误，也都无法从其他记录解析该 ID。新版额外报告这条记录自己的字符串 `origin` 指向 `SRC-998` 的错误。候选修订须区分该记录能否入索引和其独立字段能否继续检查，保留旧版适用范围。 |

组织者在 Python 3.12.15、PyYAML 6.0.4 和 jsonschema 4.26.0 下，用两个提交各自的 `scripts/` 和 `schemas/` 执行了上述 CLI 校准。输入以旧版三个仓库样例为底稿。正例 `SRC-001.yaml` 用于变换字段，反例 `dangling-reference.yaml` 提供 `REQ-004` 和独立的 `SRC-999` 诊断，`missing-acceptance.yaml` 将 `acceptance` 补为 `["测试来源仍可解析。"]` 后提供引用 `SRC-001` 的 `REQ-005`。同一批输入原样在两版运行。以下批次的退出码均为 1，异常、摘要及逐条诊断才体现行为差异。

| 批次 | 输入与变化 | 旧版 CLI | 新版 CLI |
| --- | --- | --- | --- |
| 1 | 仅 `REQ-004` | 1 条错误 | 1 条错误 |
| 2 | `SRC-001` 的 `relations` 设为 `REQ-002` 字符串，另有 `REQ-004` | `AttributeError` | 2 条错误 |
| 3 | `SRC-001` 的 `kind` 设为 `[source]`，另有 `REQ-005` 和 `REQ-004` | `TypeError` | 2 条错误，无 `REQ-005` 的缺来源 |
| 4 | 由批次 3 移除 `SRC-001` | 2 条错误 | 2 条错误，含 `REQ-005` 的缺来源 |
| 5 | 批次 2 的 `relations` 改为 `[]` | 2 条错误 | 2 条错误 |
| 6 | 批次 2 的 `relations` 改为 `[REQ-002]` | `AttributeError` | 2 条错误 |
| 7 | `SRC-001` 的 `id` 设为 `{bad: SRC-001}`、`origin` 设为 `SRC-998`，另有 `REQ-005` 和 `REQ-004` | 3 条错误 | 4 条错误，新增 `SRC-001` 文件的缺来源 |

校准只覆盖一个校验器的两个提交。输入改写属于针对真实版本的验证探针。正式采集前保存题目、共同输入、两种等义材料及参考答案的版本和哈希，并记录分配。校准参考、评分表及其他组的附加材料留在组织者侧。

## 评阅与结论口径

每题分别核对结论、必要版本和条件、证据定位三个要素，各记满足或缺失，另记无依据推断和遗漏。每题可同时涉及多种能力，按题目主判据统计，将其余成立的观察单列。先对齐主张的版本和前提，再判断证据是否冲突。证据无法裁定时记录欠缺的证据。修订建议另核对变更内容、支持证据和保留的历史条件，正式授权状态由作者单独裁定。

各组先按独立会话汇总，再展示逐项差异。记录实际分发的字符或 token 数、材料顺序，以及共同提取、各格式整理和复核工时。若 B、C 均改善同类判断而彼此接近，阶段观察支持整理的价值，图谱关系结构的增量仍待证据。该对照的结论限于给定任务中提供的材料表示。
