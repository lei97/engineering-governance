# 校验器版本交接复核

维护者正在更新批量校验器的交接记录。请根据材料判断历史说法及其适用条件，交付供维护者复核的说明。`history.md` 是历史材料，`evidence.json` 收录同一批输入在两个提交上的实际 CLI 输出。`source/old` 和 `source/new` 提供两个提交的源码、Schema、规范和测试。阅读同目录提供的材料。

1. 对于批次 1，旧材料中的缺来源判断在目标版本是否可用？说明范围和证据。
2. 对于批次 2，从旧版切到新版时，历史的批次结果预期应如何处理？说明版本边界和证据。
3. 对照批次 3 与 4，区分源记录字段校验、来源 ID 能否解析和同批独立诊断。说明两版中各项检查的实际结果及原因。
4. 一份交接草稿把历史报告解读为“旧版 `relations` 为任意列表时都会崩溃”。用批次 5、6 和代码核查这句话，并说明新版的表现及两版不能直接相互替代的条件。
5. 用批次 7 核对历史材料中关于非字符串 ID 的说明。提出一条带版本、条件和证据的维护建议，并注明其确认状态。

先为七批输入逐版列出是否正常走完批次、未捕获异常及类型、是否输出正常摘要、实际得到诊断的文件及字段或原因、相关独立检查是否执行、跳过或未到达。区分对外输出与从源码推得的执行过程。再按问题分别给出判断、版本与必要条件、证据位置。证据不足时指出缺少的材料。位置可用 `evidence.json` 的批次与版本、历史材料段落号，或版本快照内相对路径与行号。

在分配目录内写出 `response.md`。运行只需使用本包内资料。若复跑已有命令，允许使用给定依赖和独立临时目录。保持输入文件原样。请勿读取其他项目、当前工作区、Git 历史、其他会话或网络。报告实际用过的外部材料或工具限制。
