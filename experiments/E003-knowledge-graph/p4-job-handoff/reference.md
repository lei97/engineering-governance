# Job 案例参考判据

评阅对象为五题的独立会话答卷。以下两轴各自统计，不合成总分。逐行记满足、部分满足、错误或遗漏。给出一处可定位的证据并覆盖该行实质条件才记满足。等义表述和有依据的保留判断均可得分。另逐条记无依据断言、混淆事件或授权的情况。相邻行共享证据，不能视为独立样本。

## 知识恢复

| 判据 | 题 | 所需事实和证据 |
| --- | --- | --- |
| R1 | 1 | H1 的 3 月同一状态有 `Failed=True`、`ready=2`、`terminating=1`。5 月是另一次试验，记录 `Failed` 先于最后 Pod 的终态，约 26 秒。两者不合并成一条轨迹，构建未记明。 |
| R2 | 2 | H2 的内置控制器条件：`FailureTarget` 或 `SuccessCriteriaMet` 可先出现，终态 `Failed` 或 `Complete`。`JobManagedBy` 与 `JobPodReplacementPolicy` 以 OR 控制延后，等待未入账 UID 与终止中 Pod 的检查是两道条件。 |
| R3 | 3 | H3 的配置和观测：`suspend=true` 与 `completions=0`，旧版有 `Complete`、新版报告 `Running`。早期认为有终止中的 Pod，另一复现报告无 Pod，日志指向缺 `status.startTime` 的终态更新被拒。 |
| R4 | 3 | H3/H4 的实现和时序：两个固定提交的 `job/strategy.go` blob 相同，`JobManagedBy` 默认 `false→true`，`JobPodReplacementPolicy` 两版均默认开启。已合并的修复豁免特定校验，回移至 `v1.32.7`，有维护者或报告人复验。 |
| R5 | 4 | T1 的 EKS 版本、`SuccessCriteriaMet=True/CompletionsReached`、已有 `startTime`、`terminating=0`、未入账成功 UID 及片段无 `Complete`。这是一份现场状态片段和 Helm 等待的报告。 |
| R6 | 5 | T2 的原报告人归因于持续修改 Pod 的 Kyverno 策略。它是关闭说明，缺同 UID 的策略、请求或时序证据。 |

## 知识有效性判断

| 判据 | 题 | 应判定的范围、结果和理由 |
| --- | --- | --- |
| V1 | 1 | H1 的该次历史观察成立，`Failed` 表示已记录 Job 失败。认为最后 Pod 已终止的推论不成立。公开轨迹没有实际资源归还时间，Kueue 讨论说明风险，未证明该批次何时归还配额。 |
| V2 | 2 | 上游适用内置控制器及对应门控。提前条件只表示成败判据，`terminating=0` 单独无法保证终态发布，未入账集合及其他前提仍相关。Pod 终态状态也不足以裁定外部资源归还。 |
| V3 | 3 | H3 的独立复现支持验证路径拒绝而非等待 Pod 终止。`Running` 或 `SuccessCriteriaMet` 不能证明真的有 Pod 运行或终止中。最初 2 秒状态片段本身无法定位根因，归因采用后续独立复现及固定源码。 |
| V4 | 3 | 区分终态延后 OR gate 和仅 `JobManagedBy` 的增强校验。补丁只在同时暂停与零完成数时对缺时间检查豁免，未给所有 Job 补写 `startTime`，也不保证每次无终态回归都被修好。 |
| V5 | 4 | T1 证据不足以确认现场配置 `spec.successPolicy`。正常完成计数路径也能发提前条件，`CompletionsReached` 与匹配显式策略的 `SuccessPolicy` 原因分开。配置片段的未展示不能证明部署绝无该字段。 |
| V6 | 4 | `terminating=0` 推不出应立即写 `Complete`。T1 的未入账 UID 在上游代码的同一次 `enactJobFinished` 检查中足以挡住终态。对具体 EKS 执行轨迹及持续未入账的原因保持证据边界。未入账字段不是正在运行或物理资源未释放的清单。 |
| V7 | 4 | 不能直接套用旧 `startTime` 回归。T1 这份快照中有时间、示例配置也无旧缺陷的两个前提，发行商构建不可仅凭上游标签断言同一二进制行为。不同快照不能排除未知的其他状态更新问题。 |
| V8 | 5 | 关单作者归因应记录。持续修改具体阻止哪次更新或删除仍证据不足，指出同 UID 的策略变更、Webhook 或 API 日志、Pod finalizer 与 Job 更新时序中的至少一项及用途。 |
| V9 | 5 | 某时刻节点容量或配额已归还仍证据不足。列出与该 Job/Pod 时间和身份关联的实际资源或配额记录。避免由 `terminating=0`、未入账 UID 或关单推断归还。 |
| V10 | 5 | 候选修订可追溯地保留历史配置、门控和证据边界，分别记录状态发布、具体根因、资源归还的凭据。修订提议待维护者确认。 |

对 T2 直接承认作者报告并用「无法独立确认」限定，应得分。接受无 Pod 的证据限于 #132144 的独立复现。把它当作 EKS 现场的 Pod 轨迹属于跨事件推断。#16 校准试答及其金标从该正式案例的统计中排除。
