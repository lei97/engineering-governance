# E004 · 按需追溯与连续变更

2026-11-26。问题来自《从理论构建到 Context 治理》第 5–6 节，并接续 E003 复盘留下的知识获取问题。工作模式为 creative。以下任务、样例和历史记录均为构造材料。它们用来隔离两类可复跑的回归。

## 问题与判据

在相同模型和任务下，给 Agent 一个有限的原始历史查询窗口，是否能增加其在连续两次变更中守住已有行为的机会？它能否在实现前发现潜在回归？主要结果为每条链两次交付的留出检查全通过率。各阶段的新功能、兼容检查和两项关键风险分开报告。观察到 B 通过而 A 失败才记录这组样本的交付增量。若交付结果持平，预测与证据使用仍可单独比较。

| 阶段 | 新需求 | 主要预测判据 |
| --- | --- | --- |
| T1 | 为出库事件增加按仓交付 | 明确预测按仓号等值过滤会丢掉无仓号的撤销事件，导致接收端保留本应撤销的状态。 |
| T2 | 给出库交付增加可续读分页 | 明确预测只按投递行推进游标会在过滤后无投递的批次停住，并指出游标应推进到扫描完的原始事件。 |

预测必须在提交首个可评分补丁前封存，包含可观察的结果和当时的依据。判分以封存文字为准。引用命中另记，用相应文件、工具记录和代码核对。当前代码可支持两项推断，任务文字也给出已有接收行为与扫描预算。因此 A 有机会独立达到上限。B 的早期日志能提供具体运行例子，其适用条件仍需与当前代码和协议核对。

## 分组和交接

- **A · 当前资料。** 提供当前代码、公开测试和本阶段任务。
- **B · 按需追溯。** 在相同材料之外提供原始日志和变更的目录。每阶段最多成功读两份、合计不超过 2,048 字节。目录只列修订号、文件名、大小，检索路径由会话选择。第二阶段目录含本链前一阶段的实际补丁。
- 同一 Python 版本和模型配置，每组两条链。阶段一从同一基线出发。阶段二换新会话，从各自前一阶段提交的代码出发，使用相同公开测试和任务。预测、答卷以及留出分数由组织者保管。T2 对组间差异的解释以整条链为单位，因为起点可能已受 T1 影响。
- 分发前按匿名编号固定组别。每个阶段最多等候八分钟，缺交件和读取越界与普通验收失败分开记录。目录和预测封存由工具记账。目录分离依赖会话遵守访问约定，共享机器无法审计目录外的全部访问。

## 复跑与成本

先用正确实现和两种局部错误实现校准留出检查。评估时只在独立目录重放原始交付源码。公开测试和留出脚本随实验归档，评分不改写答卷。留出测试给出逐项通过状态，预测按上表逐条解释。

记录可用历史大小、目录与历史文件返回字节数、成功及被拒绝的工具调用和派发标记到封存的墙钟时间。检索字节数是一次实际返回的内容量。墙钟时间包含队列等待。完整工具调用数、模型 token、人力整理与长期维护工时属于未测变量。单案例、小样本的结果用于描述这组输出。显式知识库对照、自然项目的维护成本和跨更多版本的效果留给后续案例。

## 执行顺序

1. 冻结任务、分组、历史材料和留出判据，核对校准结果。
2. 派发 T1，锁定预测和补丁，验证交接包；按原分组派发 T2。
3. 重放八份交付，逐项核对预测、路由和游标，归档原始结果并提交。
