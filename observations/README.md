# 工程观察

Imagine、实际工作或其他项目在正常开发中出现值得回查的知识问题时，可以在本目录记一份观察。优先关注带来重复分析、判断错误、返工或沟通成本的事件。一件事写一份短 Markdown，按需记录。

写清事件发生时能查到什么，以及后来才找到什么。把亲历现象、已有证据和待验证的解释分开。某项原因暂时无法确定时，保留待核实的状态。等多个真实事件显示出可能的共同机制，再评估是否值得开展对照实验。

## 可复制模板

```markdown
# 工程观察 · <事件标题>

## 背景
当时在做什么任务？涉及哪个项目、版本或工作阶段？

## 实际现象
人或 Agent 做了什么？实际遇到了什么问题？

## 已有知识
当时有哪些相关需求、文档、代码、测试或历史经验？它们分别适用于什么范围？

## 知识缺口
哪些信息当时找不到、被遗漏，或在找到后用错了？能确认到哪一步？

## 工程影响
实际发生了哪些重复分析、错误实现、返工或沟通成本？

## 证据
列出能回查的提交、会话、测试或运行日志。必要时注明版本和时间。

## 待验证的解释
有哪些可能原因？还缺哪些证据才能区分它们？
```
